# Sprint 1 test cases — PB-02, PB-03, PB-04, PB-07

## Test approach

- Unit tests cover boundaries and validation without a network.
- Component tests cover field feedback, failure-state retention, list status and deletion confirmation.
- Route tests (`apps/backend`) cover authentication, authorization and SQLSTATE-to-HTTP mapping without a real database.
- Database tests cover atomic persistence, constraints, cascade deletion and RLS with multiple identities.
- Playwright covers unauthenticated protected-route access.
- Manual execution uses the shared Supabase project only after its migration is deployed.

Test specifications remain separate from execution results. Never store account passwords in this file, Jira, Git, screenshots or evidence links.

## Clarification requirement buckets (venue/equipment/registration split)

Found during hands-on testing: the original single "requirements" permitted-fields bucket bundled venue, equipment and registration together, so a coordinator who only needed the registration answer fixed had no way to grant that without also unlocking equipment and venue editing. Split into three independent buckets; the retired combined bucket stays valid on already-stored rows for backward compatibility.
